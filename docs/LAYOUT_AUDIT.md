# BRAMANDA layout audit

## Scope

Inspect all existing storefront, account, customer purchase/payment, Owner and Staff templates. About is `/#about`; Search and New Arrivals use Shop query parameters. Tracking and cancellation history are inside order details. No standalone versions of these pages were invented. Django admin is excluded and does not load the storefront base template.

## Findings and implemented corrections

| Component / pages | Root cause | Correction |
| --- | --- | --- |
| Storefront / Shop / Search / New Arrivals | Two shared container definitions cap content at 1280px; percentage gutters differ from header/footer and homepage. At 1920px this leaves 320px per side. | One fluid gutter and container system; wider collection area with balanced desktop columns. |
| Homepage | Hero, values, featured edit and stories each define separate percentage insets; featured edit caps at 1280px. Mobile hero enforces 620px regardless of its copy. | Align section gutters, keep editorial whitespace, and make mobile hero height follow its content. |
| Sparse collections | Fixed grid columns can leave awkward empty tracks; the single featured image can become oversized at wide widths. | Keep sparse cards at practical fashion-image proportions and retain editorial content beside sparse featured collections. |
| Product details | Six-percent column gap grows with screen width; existing gallery height limit fights its aspect ratio. | Bound detail width and fluid column gap, preserve complete product images and practical information width. |
| Cart / checkout / confirmation / orders / tracking | Competing 1100/1180/1200px caps and 90/94% widths misalign headings and content. | Shared purchase-page container with an intentional content cap; keep summary panels and form widths practical. |
| Login / registration / profile / cancellation / payment documents | Narrow widths are generally intentional and readable. | Preserve readable caps, align gutters and adjust only verified overflow/spacing problems. |
| Owner and Staff pages | Overall shell cap at 1720px leaves margins at 1920px; tall cards and stretched two-column panels can create blank panel space. | Full-width portal shells, compact balanced metrics, panels aligned at their tops; keep sidebar and horizontal table scrolling. |
| Owner Reports and catalog/staff forms | Four metric tracks leave the fifth Report card on an isolated row; existing capped form grids are intentionally readable. | Fit the five Report cards in one wide-desktop row and preserve existing form grids/caps. Portal filters benefit from the wider shell. |

## Verification

## Shared CSS architecture

The shared layout tokens live in `static/css/base.css`: `--page-gutter`, `--content-width`, `--purchase-width`, `--account-width`, `--section-space`, and `--layout-gap`. `.container` has one canonical definition. Homepage reuses the same gutters; storefront purchase/account pages deliberately cap their widths. Portals remain independent of storefront widths. Page-specific collection, detail and inventory corrections are scoped to their components and reuse existing responsive breakpoint blocks. No negative margins or absolute-positioning shortcuts were introduced.
